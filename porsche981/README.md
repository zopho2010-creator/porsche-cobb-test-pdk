# Porsche 981 OBD 原型研究

> 本目录的验证范围是离线、模拟和源代码检查。未验证真实适配器、台架控制器或实车。

原型针对 2014 Porsche 981 3.4L 的 SDI9 ECU 和 PDK TCU。这里保留通用 J2534 适配器层、控制器软件标识查询、离线 SDI 压缩编解码、PDK 备份与恢复参考模型，以及配套单元测试。

| 历史成果 | 证据与范围 |
| --- | --- |
| 设备镜像与控制器协议 | 后续离线研究从 POR-007 设备镜像识别出了车辆侧组件。静态分析为 ECU/PDK 标识、分段和读取流程提供证据。实际车端报文及适配器时序仍无采集结果。 |
| J2534 与标识 | 原型实现了 Windows 适配器登记检查、VIN 查询和 ECU/PDK 软件标识读取。历史检测在当时的 Windows 主机上返回 `drivers: []`。普通 USB 串口或 ELM327 的枚举结果不足以确认 J2534 支持。还需要匹配位数的厂商 PassThru v04.04 驱动以及 CAN/ISO 15765 能力。 |
| 离线编解码 | SDI 编解码器可对合成数据进行压缩往返，并拒绝截断、越界引用和非法尺寸。原型还研究了 ROM 校验、分段和传输准备。 |
| PDK 原车程序备份 | Q033/Q061 模拟流程对两个 2 MiB 读取得到的内容进行一致性检查，并绑定控制器身份和软件版本，保留原始备份。 |
| 写入与还原保护 | 历史模拟覆盖了无备份、备份损坏、备份过时、身份不符以及恢复中断。还原范围限定于已确认的程序分段，EEPROM 和防盗数据未纳入。原型阻止了新 ECU 写入，因为缺少对实际原车完整读取和恢复的验证。 |
| 回归结果 | 原工作台最终历史回归记录为 Windows x64 和 x86 各 178 项通过，使用模拟驱动和合成数据。该结果适用于当时的完整原型。此仓库中的离线测试是其子集。 |

## PDK 备份、写入和恢复模拟

运行 [离线参考模型](simulate_pdk_workflow.py)可复现 25 个 PDK 场景。脚本用合成数据检查备份往返、已有备份保护、身份与哈希校验、写入中断、写后校验失败和无法恢复通信等情况。写入与读回作用于 Python 内存中的模型，备份文件写入临时目录。

模型使用合成分段与数据，不调用 J2534 适配器。实际刷写和恢复能力仍需台架及实车验证。

## 离线测试

在本目录用 Windows Python 3.12 或以上运行。模拟适配器测试不连接车辆。编解码器有一项可选原件回归，归档未附原厂 ROM，因此会跳过。

```powershell
python simulate_pdk_workflow.py
python -m unittest discover -s tests -v
```
